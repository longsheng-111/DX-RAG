## 2. 摄入任务队列化

### 2.1 选型：ARQ（不选 BackgroundTasks / Celery）

- FastAPI BackgroundTasks：进程内执行，重启丢任务、无重试、无并发上限——只是把阻塞挪后，不解决问题。
- Celery：对单 worker 场景过重。
- **ARQ**：asyncio 原生、Redis 做 broker（已备）、自带重试/超时/job 查询，worker 与 backend 共用镜像和代码。

### 2.2 改造设计

```
POST /api/upload
  1. 流式写盘（保留现有 413 限额逻辑不变）
  2. files 表落记录（status=pending）+ ingest_jobs 落记录（status=queued）
  3. arq enqueue("ingest_file", job_id)
  4. 立即返回 { job_id, file_id, status: "queued" }        ← 契约变化点

GET /api/ingest-jobs/{job_id}
  → { status, progress, error, chunk_count? }              ← 新端点

worker（新进程，同镜像不同 CMD）
  ingest_file(job_id):
    status=running → process_file() → 逐页/逐块更新 progress
    → 成功 status=done（files.status 同步）
    → 失败 status=failed + error，重试 1 次后放弃
```

要点：

- **前端最小适配**：上传成功后从"等待完成"改为轮询 `/api/ingest-jobs/{id}`（2s 间隔，已有进度条 UI 可复用）；旧响应里上传完成才返回的字段（chunk 数等）挪到 job 查询结果里。
- **worker 部署**：docker-compose 加一个 `worker` 服务，同 backend build，`command: arq app.worker.WorkerSettings`；本地开发 `start.bat/sh` 加一个可选窗口。
- **并发上限**：ARQ `max_jobs=2`（embedding 是 CPU/内存密集，多了反而拖垮机器）；队列积压时上传接口照常收，排队即可。
- **失败兜底**：worker 宕机时 job 停留在 queued/running——加一条兜底：API 读 job 时若 running 超过 15 分钟无心跳，标记 failed 并允许重新 enqueue。
- 同名重传、删除文件的现有语义不变（删除时若 job 在跑，先撤 job 再删）。

### 2.3 LLM 并发保护（顺手做，半天的量）

worker 和 API 都会调 LLM。加全局信号量防止并发打爆 DeepSeek 限额：

- 新增 `app/services/llm_gate.py`：`asyncio.Semaphore(settings.llm_max_concurrent)`（默认 8）+ 429 时指数退避重试（最多 3 次，1s/2s/4s）
- `token_tracker.chat_completion` 统一走这道闸，一处改全链路生效

## 3. 并发压测

### 3.1 工具与场景

工具：**locust**（Python 生态，脚本可入库 `backend/tests/load/locustfile.py`）。

三个场景，全部打 Docker compose 起起来的完整栈：

| 场景 | 内容 | 观察点 |
|---|---|---|
| S1 基线 | 20 并发循环 POST /api/query（固定 10 个问题轮换），持续 3 分钟 | p50/p95/p99 延迟、错误率、吞吐 |
| S2 上传干扰 | S1 进行中上传一个 20MB PDF | 问答延迟是否被拉爆（队列化的核心验收：上传期间 p95 波动 < 20%） |
| S3 考官混合 | 10 并发 /query + 5 并发考官流程 | 状态机在并发下无串会话、无重复记分 |

### 3.2 产出

`docs/压测报告.md`：环境（机器/compose 配置/worker 数）、每场景延迟分布表 + 错误率、瓶颈分析（预计瓶颈在 LLM 上游延迟与 embedding CPU）、调优记录（worker 数/信号量调整前后对比）。这份报告同时就是面试讲高并发话题的实证素材。

## 4. 可选项：API Key 鉴权

若做：FastAPI dependency 校验 `X-API-Key` 头，`.env` 配置，未配置时保持开放（开发便利）；前端 axios 拦截器统一带 header。约半天。对展示项目而言价值一般，**建议放在队列化和压测之后，有时间再做**。

## 5. 验收标准

1. 上传 20MB PDF 立即返回 job_id（< 1s），后台完成后 job 状态变 done，知识库可检索到新内容
2. S2 场景下问答 p95 波动 < 20%，无 5xx
3. S3 场景后抽查会话：消息无丢失、scores 条数与作答数一致、无串会话
4. 压测报告入库 docs/
5. 全量回归：backend/tests 现有用例全过
